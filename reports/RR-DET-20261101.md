## What is hashed, and why that object

```
sha256( render_page_table( derive_page_table(ledger_lines, records_lines) ) )
```

This is the artifact the `--replay` gate compares against each committed baseline — not the
validator's printed sentence. Hashing the derivation keeps the check independent of message
formatting and of `jsonschema`, so the checker itself is standard-library only and runs in a bare
`python:3.12-slim` image with nothing installed.

Reference table: `reports/determinism-hashes.txt` (9 rows, full `sha256:<64>`, sorted, no timestamps).

| Row | What it covers |

## Environments actually compared

```
bash tools/determinism-matrix.sh
  host CPython 3.14.7        PASS  9 derivations byte-identical
  host PYTHONHASHSEED=0      PASS
  host PYTHONHASHSEED=12345  PASS
  docker python:3.12-slim    PASS
  docker python:3.13-slim    PASS
  determinism-matrix: all environments agree with the committed table
```

Five environments: three interpreters (CPython 3.12, 3.13, 3.14 — the containers are separate
builds), two hash-seed settings, x86-64. **Variance: zero mismatches.** The hash-seed runs are the
useful ones: they would catch a derivation that depended on dict iteration order rather than on
canonical rendering.

**Cross-machine** happens on push: the new CI step (`page-table determinism across environments`)
re-derives in the GitHub runner's Python 3.12 and compares against the committed table. The
rehearsal proves the step's text works in a pristine clone; the GitHub run proves the second machine
agrees, once this commit is pushed.

## Two findings worth keeping

1. **The recorded v3 hash reproduces the historical digest.** `calibration/corpus-v3` and
   `tests/m3-replay-full` both hash to `sha256:25b073cbc59a5e2c…` — the exact prefix quoted in
   `RR-M3V3`/`RR-M3FULL` as the capture-time page-table digest. The new table is therefore anchored
   to the existing evidence rather than starting a second, unrelated identity.
2. **The page table is insensitive to calibration.** Raw and calibrated records hash identically for
   both corpora. That is correct — the table records identity, slots and tokens, not confidence — and
   it is now stated rather than assumed, because a reader could otherwise expect calibration to move
   the hash.

## Scope of the claim, stated for reuse

> Page-table derivation is byte-identical across CPython 3.12/3.13/3.14 on x86-64, under three hash
> seeds, and in the CI runner. Model-output identity is a different claim: identity 480/480,
> strict `contentHash` 470/480, with the 10 divergences attributed to capture-time concurrency
> (`RR-M3FULL`).

Five environments is a measurement, not a proof. ARM, musl, Windows and 32-bit builds are not
covered, and nothing here says a hosted provider's logprobs will match a local runner.
