# RR — CALCI-20261101 — absolute calibration metrics with bootstrap intervals

**Card:** the W9 item "Report ECE with bootstrap intervals and note the n=120 limit. Do not present
point estimates as precise." The reports carried paired-bootstrap intervals for the *deltas*
(calibrated minus raw) and nothing for the absolute values.

## What was added

- **NEW `spec/calibration_ci.py`** — reads committed artifacts only (no model, no network):
  `calibration/raw-v3.jsonl` (split, gold, correctness, probabilities), the calibrated confidences
  from `calibration/corpus-v3.calibrated.records.jsonl`, and the artifact of record. Metrics reuse
  `spec/calibration_tools.py` (`ece`, `brier`) so the intervals are intervals around the statistic the
  artifact reports, not a lookalike. Percentile bootstrap, n=2000, seed 42.
- **NEW `calibration/cal-precision-v3.json`** — the committed numbers, checked in CI and in
  the local gate (`check` mode exits 1 on any drift).
- **Hub honesty paragraph** — the Current KPI values are now labelled point estimates, with the
  interval caveat named and the precision file cited.
- **`RR-M3V3` addendum** — the report of record carries the absolute intervals.

## The result, and why it matters

```
metric               point      95% CI (percentile bootstrap, n=2000, seed 42)
ece_raw_top          0.2473     [0.1751, 0.3257]
ece_raw_entropy      0.2106     [0.1536, 0.2949]
ece_calibrated       0.0302     [0.0286, 0.1201]
brier_raw_top        0.2388     [0.1697, 0.3102]
brier_raw_entropy    0.2213     [0.1560, 0.2898]
brier_calibrated     0.1726     [0.1409, 0.2077]
accuracy             0.7083     [0.6250, 0.7917]
```

**Three of the hub's release-gate KPIs are within noise of their targets at n=120.**

| KPI | Current | Target | 95% CI | Verdict |
|---|---|---|---|---|
| Calibrated ECE | 3.02% | ≤ 5% | [2.86%, 12.01%] | **not demonstrated** — upper bound is 2.4× the target |
| Calibrated Brier | 17.26% | ≤ 20% | [14.09%, 20.77%] | **not demonstrated** — upper bound sits just over |
| Decision accuracy | 70.83% | ≥ 68% | [62.50%, 79.17%] | **not demonstrated** — lower bound is below |

The point estimates read as comfortable margins ("3.02% against a 5% ceiling"). The intervals say
the corpus cannot distinguish a passing system from a failing one on these three KPIs. That is not a
defect in the calibration — the calibration *improvement* is large and its delta CI excludes zero —
it is a statement about how much a 120-row test split can support.

The ECE interval is asymmetric (upper tail 4× the point estimate). That is expected for a
bounded, skewed statistic under percentile bootstrap, and it is the honest shape: a superbly
calibrated model and a moderately calibrated one both score low on this corpus, but only the
second produces the long upper tail.

**What this means for the demo position (D2):** the numbers are publishable as *measured on a
120-row test split with stated intervals*, not as a demonstrated release gate. Raising the claim
requires more rows, not a better estimator.

## Data shape worth knowing

`corpus-v3.calibrated.records.jsonl` carries a `calibrated` block on **120 of 480 rows** — only the
held-out test split the fit was evaluated on. The script tolerates the other 360 and joins by `ref`;
a reader expecting calibrated confidence on every row would otherwise hit a `KeyError`.

## Defect found by wiring this card (a defect class, not just an instance)

The first filename for the precision artifact was `calibration/umpire-cal-v3.precision.json`.
That broke the validator outright: `spec/validate_ledger.py::load_calibration_artifacts()` globs
`calibration/umpire-cal-*.json` and calls `validate_artifact()` on each hit, which ends by computing
the data version through `artifact_core()` — and that raises `KeyError: 'labels'` on any JSON that
is not an artifact. The rehearsal caught it (step 04 red in a pristine clone), and so did the local
gate.

Two fixes, because the instance and the class are different problems:

1. **The file moved** to `calibration/cal-precision-v3.json` — out of the artifact namespace, so a
   precision file can never be mistaken for a calibration artifact again.
2. **The loader was made defensive** — `load_calibration_artifacts()` now skips a document it cannot
   validate instead of crashing, with the reason in a comment. Its own docstring already claimed
   "structurally invalid artifacts are not loadable"; now that is true for shapes it did not
   anticipate, not only for artifacts that parse.
