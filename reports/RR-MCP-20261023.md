# RR-MCP-20261023 — local stdio MCP integration (OpenCode + Hermes)

**Status:** implemented; OpenCode live `decide` + `validate` verified against the
v2 artifact.  Hermes-side configuration is being finalized separately.  **Spend:**
zero provider spend; local pinned llama-server only.

## What was built

`mcp_server.py` is a dependency-free (Python stdlib) stdio MCP server that wraps
the existing `harness/umpire.py` library.  It is the common surface for both
agent harnesses; there is no second decision implementation.

Tools (short names so the harness prefixes stay readable):

| tool | behavior |
|---|---|
| `decide` | one `umpire.decide` call; returns key, raw probabilities, raw confidence, optional calibrated sidecar, `ref`, `contentHash`, ledger paths |
| `pins` | pin identities from `harness/pins.json` |
| `health` | pinned llama-server `/health` |
| `calibration_info` | read-only artifact identity/test metrics |
| `validate` | xCABI validator on a ledger/records pair |
| `replay` | page-table replay against a baseline |

The server speaks the classic MCP `initialize` handshake and newline-delimited
JSON-RPC over stdio.  It does not listen on a port, start a runner, use OAuth, or
store provider credentials.

OpenCode names tools `<server>_<tool>` (`umpire_decide`, `umpire_pins`, ...);
Hermes names them `mcp_<server>_<tool>` (`mcp_umpire_decide`, ...).  Under
OpenCode's default Code Mode they are called as `tools.umpire.decide(...)`.

## Protocol issue found and fixed

The first implementation returned a plain JSON object from a `tools/call`
handler.  MCP expects a `CallToolResult` envelope:

```json
{"content":[{"type":"text","text":"…"}],"structuredContent":{…},"isError":false}
```

OpenCode's Code Mode surfaced the malformed result as `null` even though the
server log showed a correct object.  `mcp_server.py` now wraps every handler
result with `content` + `structuredContent`, and returns tool-level errors with
`isError: true` instead of leaking a JSON-RPC internal error.  The regression
test is `mcp_server_test.py` (7 tests).  It covers tools/list, the pins envelope,
the validate fixture, v1/v2 calibration info, the input-error envelope,
unknown-tool errors, and a fake-runner `decide` end-to-end check that verifies the
calibrated block, `calibrate:false`, and contentHash parity without a model
request.

## OpenCode

Configuration lives in:

- `~/.config/opencode/opencode.jsonc` — global entry with absolute paths;
- `opencode.jsonc` in this repo — project entry with relative paths.

The live OpenCode session discovered six tools (`mcp connected server=umpire
tools=6`).  Code Mode calls for `pins`, `health`, `calibration_info`, `validate`,
and `replay` returned structured objects after the envelope fix.  A live v2
`decide` then returned `key=billing`, raw confidence 0.951, and calibrated
confidence 0.631579 from `cal-v1:aceb881587b3b3a6`; its ledger/records pair passed
the validator (`PASS 139 checks`, negatives 12/12).  `calibration_info()` with no
arguments returned the v2 artifact and test n=120 metrics.

`opencode mcp list` is not a reliable health check in this build: it starts a
short-lived server, closes stdio, and reports the clean EOF as “Connection
closed”; the running session is the authoritative check.  The same build reaped
an idle local server after ~80 s in one observation; touching the config
reconnected it and rediscovered all six tools.  This is a harness lifecycle quirk
to account for in long sessions, not a crash in `mcp_server.py`.

## Hermes

The same server is registered as `mcp_servers.umpire` in
`~/.hermes/config.yaml`.  `hermes mcp test umpire` connected and discovered six
tools.  The final Hermes lifecycle/config details are owned by the Hermes
integration workstream; the server contract above is stable.

## Calibration scope

The server can apply a fitted artifact with `UMPIRE_CALIBRATION` (or the
per-call `calibration` argument).  The artifact is per pin + seed + label set +
distribution.  `calibrate: false` is available for a different label set or for
raw-confidence-only use; a mismatched artifact fails before the model request.
The live integration uses the fitted corpus-v2 artifact
(`calibration/umpire-cal-v2.json`, `cal-v1:aceb881587b3b3a6`, isotonic/1); v1
remains historical.

## Limits / security

- Local trusted-user model; no remote transport, authentication, or tenant
  isolation.  Do not expose stdio through a remote bridge without adding those.
- One server process serializes decisions with a lock.  Multiple processes
  sharing one ledger file are not coordinated; use one ledger directory per
  process or a single process.
- State text can contain secrets; choose a private `UMPIRE_LEDGER_DIR` and a
  retention policy.
- Latency is the pinned local model's (~10–15 s/decision on the reference 4-core
  CPU), not a hosted SLA.
- Calibration is an estimate of P(key correct) on the fitted distribution; it is
  not a correctness guarantee.
