# RR-RFC01-20261031 — xCABI RFC-0.1 profile adoption (umpire side)

**Status:** landed. The decision ledger declares the RFC-0.1 R0 version boundary and
prices a deliberate re-decide as R1 `intentional_rerun`. ctxvm's replay of
`fixtures/ab-demo.ledger.jsonl` now reports **0 violations** where it reported **3**.
**Scope:** local-only (T14); no capture, no model call, no calibration artifact touched.

## 1. Why

ctxvm's RFC-0.1 proposal (`design/rfc-0.1-proposal.md`) documents this repo's friction:
umpire maps `decide()` onto xCABI pages, and the reference replayer reported three
`faultOfResidentPage` violations on umpire's *intended* A/B behaviour, because a
deliberate re-execution was overloaded onto `page.fault source:"tool_recall"`. D4
(2026-10-30) approved RFC-0.1; the ctxvm side landed 2026-10-31 (`36cec7c`), leaving
"umpire fixture regeneration" as the recorded cross-repo tail.

`tool_recall` means a page was re-fetched because it had been paged out. **umpire never
pages anything out.** Every fault it emits is deliberate, so the old source was a
misdescription of its own behaviour, not merely a schema mismatch.

## 5. Decisions recorded

- **The calibration corpora stay v0.** `calibration/corpus*.ledger.jsonl` are captured
  artifacts whose hashes are the calibration of record (v3 `25b073cbc…`), referenced by
  the hub, the packaging product and RR-M3V3. Re-minting them would break provenance for
  no semantic gain: they validate under the v0 branch, and a v0 ledger is a true statement
  about a capture that predates the field.
- **Captured fixtures are migrated, not re-captured.** `ab-demo`/`live-demo` came from the
  M1 harness run against a live model; re-capturing needs the pinned llama-server and would
  change hashes. The migration is a profile change only and the audit above proves it.
- **`latencyMs`/`turn` on `page.declare` (ctxvm R4/R5) are not adopted here.** The ledger's
  `page.declare` carries no turn, and umpire measures decision latency in its *records*
  (`latency_ms`), not in xCABI. Adding those would be invention, not adoption.

## 6. Deviations, discoveries, not done

- **Discovery: two standing negatives were vacuous.** `fault-source-semantic` (and any
  other case built on a hand-made fault hash) failed for *incidental* reasons — the fault
  did not name the resident slot and the record joined no declared slot — so the case
  would have stayed red even if L4 regressed. Both fault-source cases now use the real
  response hash and fail for exactly one reason, the profile rule. Fixed in this card
  because a test that passes for the wrong reason is worse than no test.
- **Deviation: no L3 unknown-version branch.** The vendored schema pins
  `schemaVersion` to `const: "0.1"`, so an unknown version never reaches the profile
  checks — it is a schema error. A branch for it would be unreachable dead code; the
  negative case proves the schema rejects it instead.
- **Deviation from 00-SPEC §7's literal instruction** ("do not edit its semantics;
  re-vendor"): the previous vendored file was a *reorganized* copy, so a literal re-vendor
  is a structural replacement. That is what was done — ctxvm's file is now the file, plus a
  provenance `$comment`.
- **Not done:** `README-MCP.md` (absolute-path cleanup) was already modified in the working
  tree and is left for its own commit; `hermes/` and `research/` remain untracked by
  decision (`research/` is now correctly ignored).
