## 6. Afternoon — the transfer experiment actually run (12:17 → 13:35)

Five more commits, all in this repo, all mine. The morning index said the transfer run was
"queued on owner GO"; it ran, and then it ran again.

| Time | Commit | What it was |
|---|---|---|
| 12:17 | `cb9ee8e` | Arm corpora frozen **before** the run (provenance + checksums), so capture meta pins a clean head |
| 12:52 | `2b94c6a` | The experiment: A1/A2 decoded, 90 rows each, 32 min, no spend |
| 12:59 | `8ce7e6c` | **Amendment 1** — arms extended to the validation split, frozen before the second run |
| 13:35 | `47e0ee0` | The extended result, the verdict, and the recommendation to stop |

**Run 1 (n=90).** Both arms returned "no detectable degradation" while their point estimates
(+0.068, +0.058) were three times the +0.02 materiality threshold. The rule could not fire. That
was diagnosed as a **power failure in my own design**, stated as such: the pre-run probe had
already measured ±0.04 noise at n=120, so a CI at n=90 was ~±0.07.

**Amendment 1.** Each arm gained the 90 validation rows whose gold is not the dropped label, with
train explicitly excluded — the map of record was fit on train, so A0 would have been flattered
and the degradation manufactured. The amendment was written before the second run, with the cost
(≈32 min, no money) and the expected interval (~±0.05) stated in advance.

**Run 2 (n=180).** The interval tightened as predicted and **the effect shrank**:

```
A1  ECE 7.50% → 12.23%   Δ +0.0473 [-0.0048, +0.0923]
A2  ECE 4.93% →  6.81%   Δ +0.0188 [-0.0488, +0.0723]   ← below the threshold
```

So the morning's "ECE doubles" reading was subset luck. The honest statement now: removing a label
raises calibrated ECE by roughly 2–5 points, consistently in direction, and at n≤180 that is not
separable from zero. Recommendation recorded: stop extending (the interval met its target, the
effect is at or below the threshold, and train would bias the baseline) — resolving a 2-point
effect needs a larger held-out corpus, which is an owner decision about corpus growth.

`spec/transfer_eval.py` is now v0.2 and evaluates both sets, with `check` in the local gate and in
CI, so the numbers cannot silently drift.
