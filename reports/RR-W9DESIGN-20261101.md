# RR — W9DESIGN-20261101 — calibration transfer: an exploratory probe and a frozen design

**Card:** turn the W9 transfer item from a sentence in a plan into a preregistered experiment, and
find out cheaply whether there is anything to see before spending 40 minutes of CPU on it.

**Trigger:** after the precision card (`RR-CALCI-20261101`) the absolute intervals exist, so
"calibration transfer" is the only W9 evaluation item that can be attacked without spend. W9 names
it as the load-bearing question: *the calibrated confidence is only useful if it transfers; quantify
how much it does not.*

## 1. Exploratory probe — renormalise instead of re-decode

Free, minutes, and **not** the confirmatory experiment. The v3 rows are restricted to three labels,
the remaining probabilities are renormalised, and three ECEs are compared on the test split:

```
dropped    n_test    acc  ece_raw  ece_xfer  ece_refit      gap
billing        90  0.711   0.2304    0.0391     0.0963  -0.0573
other          90  0.833   0.1422    0.1095     0.0355  +0.0740
sales          90  0.833   0.1316    0.0572     0.0522  +0.0051
technical      90  0.756   0.2100    0.0448     0.0758  -0.0310
```

`ece_xfer` = the v3 isotonic map applied unchanged; `ece_refit` = a fresh fit on the same restricted
view; `gap` = xfer − refit. Read on its own this says **no detectable transfer penalty**: the gap
changes sign across arms, and its magnitude is inside the sampling noise we measured for the
absolute metric (±0.04 on 120 rows, `RR-CALCI-20261101`).

**Why that is not the answer.** Renormalisation rescales the model's four-label distribution; it does
not re-run the model under a three-label grammar. The constrained decode is a different distribution
— `json-label-enum-v0` restricts the sample to the allowed enum — so a renormalised view can look
transfer-friendly while a real three-label run does not. The probe's role is to justify (or kill)
the confirmatory run, not to settle the question. It justifies it: there is no obvious catastrophe to
report twice.

## 2. The frozen design

`design/W9-TRANSFER.md` — preregistered before any run: arms, rows, metrics, decision rule.

- **A0** the existing 4-label v3 capture (no new run).
- **A1** re-decode the v3 test rows under `billing, sales, technical` (drop `other`, the label that
  overlaps every class).
- **A2** re-decode the v3 test rows under `other, sales, technical` (drop `billing`, the largest
  class).
- **Metric** ΔECE against A0 restricted to the same texts, paired bootstrap 95%, n=2000, seed 42.
- **Frozen rule** material degradation ⇔ ΔECE > +0.02 with the interval excluding 0; no detectable
  degradation ⇔ the interval includes 0; anything else is "small, possibly real".
- **Cost** ~90 decisions per arm at ~12 s each, ≈18 min per arm, CPU only, **no monetary spend**.

A negative result is declared a result in advance, so it cannot be quietly reframed afterwards.

## 3. What was deliberately not attempted

- **Domain transfer.** There is no second-domain corpus, and authoring one ourselves would deepen the
  "single project-authored corpus" caveat rather than relieve it. It stays open and is listed as a
  limit in the design.
- **Refit cost.** Re-decoding the train split to refit under the new label set would double the run
  and answer a different question. Deferred.
- **Baselines (kNN / logistic / fine-tuned / stronger model).** All four need embeddings, training or
  an API. Free-tier cannot honestly deliver the versions W9 names, and a TF-IDF substitute would be
  a different experiment wearing the same label. Left open, flagged for the owner.
