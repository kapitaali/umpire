# RR — CI-1 — 20261031

**Card executed:** give umpire a GitHub-side CI, and the same "test the workflow before a
push" tool the ctxvm repo just gained.
**Trigger:** the owner pushed umpire and asked to check that something actually runs on
GitHub's side. It did not: umpire had no `.github/workflows/` at all. Every gate in this repo
was local-only.

## What was added

- **`.github/workflows/ci.yml`** — two jobs, both offline, no model and no GPU:
  - `gates` (11 steps): ledger conformance over the four fixtures (207 checks, 14/14
    negatives) · page-table roundtrip per baseline (4 BYTE-IDENTICAL) · the calibration
    corpora (v2 + v3, raw and calibrated records) · the v1/v2/v3 checksum families ·
    `mcp_server_test.py` · `calibration/test_calibration.py` ·
    `harness/test_replay_audit.py` · `spec/test_packaging.py`.
  - `hub` (4 steps): `open-data-products` SDK, then `bash spec/build_hub.sh check` —
    regenerated `hub/` must be byte-identical to the committed files.
  - `permissions: contents: read`; `push` on main, `pull_request`, `workflow_dispatch`.
- **`tools/run-ci.sh`** — the local mirror: same steps, same order, one command
  (`bash tools/run-ci.sh`). Verified: `ALL GATES GREEN`.
- **`tools/ci-rehearsal.py`** — the tool from ctxvm's CI-1 card, unchanged in substance: it
  clones the repo, overlays the working tree (so an uncommitted workflow edit is testable),
  then runs each job's `run:` steps in order with a throwaway virtualenv per job, stopping a
  job at its first failure. One portability fix came out of reusing it here: neither repo's
  default python has PyYAML, so the tool now bootstraps a parser venv itself instead of
  assuming `venvs/odps`.
- **`README.md`** — repo conventions gain the CI bullet, including what is deliberately not
  in CI.

## Deliberately not in CI

`harness/test_m1.py` and the M2 live gate need the pinned llama-server on
`127.0.0.1:8081`. They are capture-session gates, not CI gates. Putting them in CI would mean
shipping a model into the runner, and a red run would say nothing about the code.

One bug found and fixed while wiring the mirror: the calibration checksum files list
repo-root-relative paths, so `cd calibration && sha256sum -c checksums.sha256` fails on all
nine entries. The gate now verifies from the root. The first draft would have been a red CI
job on the first push — which is the argument for the mirror existing, and for rehearsing it.
