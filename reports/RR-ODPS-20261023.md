## Discoveries en route (contract corrections + tooling)

1. **KPI `unit` enum has no `percent`** — KPI units must be `percentage` (SLA
   dimensions keep `percent`). ctxvm never tripped this because all its KPIs were
   already `percentage`; our first pass did, one error, fixed.
2. **`contract.$ref` resolves relative to the manifest's directory** — `odps/…` +
   `contracts/…` → `odps/contracts/…` (nonexistent). Correct form: `../contracts/…`.
   (ctxvm's manifest lives at repo root, so `contracts/…` worked there.)
3. **Contract-track commands must run from the Python 3.12 venv** — `product audit`
   under the 3.14 venv reports `DATACONTRACT_CLI_NOT_INSTALLED` (the extra is gated
   `python_version < "3.13"`); with the 3.12 venv the audit resolves the local
   `$ref` and goes fully green. Same mechanism ctxvm documented.
4. **Real record shape learned while writing the contract:** `contentHash` is the
   **short-form probe `sha256:<8 hex>`** (not 64 hex), and `model_pin` is a **nested
   object** `{model, weights_hash, decoding}`. The contract text was corrected and
   `spec/test_packaging.py` now asserts both.
5. **No `gates` block exists in ODPS `productStrategy`** (ctxvm precedent, schema-
   validated): release gates = the declared KPI targets themselves, enforced here by
   `spec/test_packaging.py` (KPI parity assertions) + the DQ executable commands.
6. **Alignment residual parity with ctxvm:** `passed: true` with the single info-level
   `ODPS_SCHEMA_NOT_FOUND` finding — non-blocking, served by the linked contract.
