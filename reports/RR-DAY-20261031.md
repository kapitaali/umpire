## 3. Defects verification found (not planned work)

1. **A checksum gate that could never pass.** The calibration checksum files list
   repo-root-relative paths, so `cd calibration && sha256sum -c checksums.sha256` fails all nine
   entries. Caught while wiring the CI mirror; as first written, the job would have gone red on
   the first push. Now verified from the root.
2. **Two MCP servers, and `setup.sh` pointed at the dead one.** The root `mcp_server.py`
   (stdlib JSON-RPC, six tools) is what Hermes launches; `hermes/mcp_server.py` (FastMCP, four
   tools) cannot start under Hermes's interpreter at all — `initialize FAILED: no reply`, `mcp
   package not installed`. A fresh setup would have produced a config that never starts. The
   duplicate is deleted; one canonical server remains.
3. **`validate` and `replay` were broken in the live configuration.** The server ran the
   validator with `sys.executable`; Hermes's interpreter had no `jsonschema`, so both tools
   returned `returncode 2` with `deps: pip install jsonschema>=4` — a tool "failure" that was
   really an environment fact. Fixed with a memoised interpreter resolver (`UMPIRE_PYTHON` →
   own → `python3`/`python` on `PATH`, first that imports jsonschema) plus installing
   `jsonschema` into the launched interpreter.
4. **Tool names wrong in three documents.** The server registers `decide`, `pins`, …; Hermes
   exposes `mcp__umpire__decide`. The docs named `umpire_decide` / `mcp_umpire_decide`, neither
   of which resolves.
5. **Skill drift.** Repo `hermes/skill/SKILL.md` v0.1.0 vs installed v0.3.0, 124 diff lines of
   extra guidance. Merged to v0.4.0, written to both locations; `diff` is now empty.
