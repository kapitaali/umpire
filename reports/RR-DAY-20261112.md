# Day 2026-11-12 — umpire

## The pinned model server gets a script (RR-SERVER-20261112)

The reboot removed the model server and left the MCP processes running, so the service looked alive
while every decide failed with **connection refused** (the MCP proxies to `http://127.0.0.1:8081`,
`mcp_server.py:51`; the ~4.5 GB server is the owner's to run). The weights and the pinned binary were
still on disk, so the restart is one command — and now that command is a script:
`scripts/start-llama-server.sh`.

It starts the **pinned invocation verbatim** (from `harness/pins.json`), **hash-verifies** the runner
binary and the weights before starting (a mismatch refuses, per AGENTS.md §1), is idempotent (it never
starts a second server on a live port), waits for `/health`, and prints the last lines of the log if it
fails. `--status` and `--stop` are there too; `--stop` only ever signals the pid this script recorded,
after checking that process's command line is the pinned binary.

Every path was exercised: status → start (pins verified, ready in 2 s) → status → idempotent start →
stop → start again. The server is **left running** ✓, and the service chain was verified through the
MCP: health 200 and a real `decide` returning key `billing` with the calibration of record applied
(`cal-v1:057a5a35a9d4ec71`, calibrated confidence 0.855263) ✓. **U2/U6 are up again.**

`AGENTS.md`'s layout block gained the `scripts/` line, so the books stay true.
