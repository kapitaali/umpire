## 3. Decisions locked this card

- **The ledger is an xCABI-0.1 profile, not a new format:** allowed events only
  `session.open` / `page.declare` / `page.fault`; 1 decision = 1 turn (0-based);
  first line must be `session.open`; faults only `source:"tool_recall"`; no floats in
  ledger lines (xCABI rule — token counts are integers).
- **Minting mirrors ctxvm `packages/node/src/ident.ts` @ `361043e` byte-compatibly**
  (ASCII-only payload rule documented for v0): `tool:decide(<canonical{labels sorted,
  state}>)` incl. 120-char `#hex8` truncation; `sha256:<8hex>` contentHash over canonical
  `{confidence,key,probabilities}`; tokens = `approx4(...)`.
- **`model_pin` + `seed` excluded from the ref** (waste-pricing rationale): identical
  `(state, labels)` under another pin or seed is a priced re-decide, never a new
  identity. Same-hash re-land → fault row only (no new declare); divergent hash → fault
  row naming the **resident (first) slot** + second-slot declare — the T8/T9 semantics
  verbatim.
- **Payloads live outside the ledger** (records sidecar keyed by recomputed identity
  echoes) — mirroring xCABI's traces-are-meta design.

traces** with no shim.

## 5. Found en route (validator-first earning its keep)

- **xCABI schema asymmetry:** `page.declare` nests identity under `page.id`, but
  `page.fault` carries a **flat** pageId (`page.logicalRef`/`page.contentHash`). First
  generator draft mirrored the declare shape for faults and the vendored schema caught
  it at line 4 of fixture 1 — fixed in generator, derivation, validator, and spec
  (§2 row), then confirmed against ctxvm's own T9 tests which access
  `fault.page.contentHash` directly.
- Derivation ref-extraction had to split per-branch for the same reason.
- `ledger_of` negative-corpus helper initially returned a joined string instead of a
  line list (char-by-char `json.loads` cascade) — fixed.

## 6. Honest limits

- Fixtures are synthetic (no harness yet — M1); `weights_hash` strings are fixed
  placeholders shaped `sha256:<8hex>`.
- `canonicalJson` Python↔TS parity is guaranteed for ASCII payloads only; non-ASCII
  canonicalization (incl. `\u2028/\u2029` escaping) is M1 audit material.
- ctxvm's validator counts checks differently than umpire's (67 vs 125 across the same
  lines) — each is its own self-consistent contract; both documented verbatim above.
