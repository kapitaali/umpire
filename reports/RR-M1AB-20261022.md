## 2. Live A/B demo (`fixtures/ab-demo.*`)

Demo session: state = "I was charged twice this month and need it fixed now", labels = [billing, other, sales, technical], seed = 7.

| step | pin | result | ledger effect |
|------|-----|--------|---------------|
| 1 | qwen3-1.7b | key=technical | fresh `page.declare` slot sha256:d615c337 |
| 2 | qwen3-1.7b (same seed) | key=technical, identical hash | `page.fault turn=1` naming resident d615c337 (reproducibility) |
| 3 | qwen2.5-1.5b | key=billing, **divergent hash** | `page.fault turn=2` naming resident d615c337 + `page.declare` second-slot sha256:f8779b48 |
| 4 | qwen2.5-1.5b (same seed) | key=billing, identical hash | `page.fault turn=3` naming resident d615c337 (fault only) |

This is the exact A/B waste semantics from the proposal: identical hash re-land → fault row only; divergent hash → fault row naming the resident (first) slot + second-slot declare. Cross-pin divergence (`model_pin`/`seed` excluded from the ref) is the priced re-decide.
